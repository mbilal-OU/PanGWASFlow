# Real-input interfaces

PanGWASFlow accepts binary genomic representations that have already been generated by an upstream variant-calling or pangenome workflow. It does not duplicate those upstream callers.

## Phenotype metadata

TSV or CSV with one row per sample. The sample identifier and phenotype column names are configurable. The phenotype must be encoded strictly as `0` and `1`; PanGWASFlow does not guess biological meanings from free-text labels.

```text
sample_id\tlabel
isolate_001\t0
isolate_002\t1
```

For pyseer-style phenotype tables, specify the existing columns explicitly, for example `--sample-id-column samples --label-column binary`.

## Core-SNP or other binary feature matrix

Sample-by-feature TSV/CSV. Each genomic feature must be encoded as `0` or `1` with no missing values in the current adapter.

```text
sample_id\tsnp_chr1_105\tsnp_chr1_812\tsnp_chr2_44
isolate_001\t0\t1\t0
isolate_002\t1\t1\t0
```

This representation is suitable for a precomputed biallelic SNP matrix, unitig matrix, k-mer matrix, or another binary feature set. Missing-genotype handling remains an upstream responsibility so that missingness is never silently interpreted as absence.

## Roary/Panaroo accessory genes

`gene_presence_absence.csv` files are converted to a sample-by-gene binary matrix. A non-empty locus entry is treated as gene-family presence and an empty entry as absence.

```bash
pangwasflow prepare \
  --features gene_presence_absence.csv \
  --metadata phenotype.tsv \
  --format roary \
  --outdir results/prepared
```

## Rtab presence/absence matrices

SEER/pyseer-style `.Rtab` files are gene-by-sample binary matrices with a feature identifier in the first column and one 0/1 column per sample. PanGWASFlow validates the matrix and transposes it internally to the same sample-by-feature representation used by the other adapters.

```text
Gene\tsample_1\tsample_2\tsample_3
geneA\t1\t0\t1
geneB\t0\t1\t1
```

```bash
pangwasflow prepare \
  --features gene_presence_absence.Rtab \
  --metadata phenotypes.tsv \
  --format rtab \
  --sample-id-column samples \
  --label-column binary \
  --outdir results/prepared
```

Compressed Rtab files are supported through pandas compression inference when their file extension identifies the compression format.

## Matrix preparation

```bash
pangwasflow prepare \
  --features core_snp_matrix.tsv \
  --metadata phenotype.tsv \
  --format matrix \
  --min-prevalence 0.01 \
  --max-prevalence 0.99 \
  --outdir results/prepared
```

Preparation writes aligned metadata, the retained binary feature matrix, feature-level prevalence QC, sample-intersection details, and a machine-readable summary.

## Association analysis

```bash
pangwasflow analyze \
  --features results/prepared/features_qc.tsv \
  --metadata results/prepared/metadata_qc.tsv \
  --pcs 2 \
  --outdir results/gwas
```

The current analysis writes PCA structure covariates, an unadjusted Fisher scan, a PCA-adjusted logistic scan, genomic-inflation diagnostics, and a JSON summary. Biological interpretation requires appropriate upstream feature construction, phenotype QC, and study-specific review.

## External format validation

The `Pyseer format compatibility` GitHub Actions workflow fetches two small public test files from the canonical pyseer repository at pinned commit `60507f69ed464f55300cc631b9ea324095bdef5d`: `tests/subset.pheno` and `tests/presence_absence_smaller.Rtab`. The files are fetched at runtime rather than copied into PanGWASFlow. The workflow verifies that 50 samples align, features survive QC, and both baseline and PCA-adjusted association outputs are produced.

This is a file-format and workflow-integration validation. It is not presented as a biological result or as a replication of the full pyseer penicillin-resistance tutorial.
